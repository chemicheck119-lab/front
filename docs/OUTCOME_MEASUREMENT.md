# 서비스 변경 전후 측정

## 문제와 기준선

현업 피드백은 필요한 정보를 적은 조작으로 얻는 것이 목적이라고 지적했다. 이번 비교는 그중 원문을 보려는 추가 조작만 측정한다. 기존 로컬 원천 패널(`1e575ca`)은 성공한 조회 결과를 접힌 `details`로 표시한다. 현행 화면(`d11ae03`)은 검색한 물질의 화재 항목 원문을 바로 표시한다.

이 기준선은 과거 공모전/해커톤 제출 화면 또는 상용 서비스가 아니다. 실제 보관 KOSHA 후보는 여전히 승인 대기이므로 실제 자료 승인 게이트를 열지 않고 동일한 합성 입력을 사용했다.

## 성공 기준과 비교 조건

- 주지표: 조회가 성공한 뒤 기본 화재 항목 본문을 보이게 하는 추가 클릭 수.
- 기준선 측정: 추가 클릭 1회가 필요했다. 개선 목표: 같은 본문을 추가 클릭 없이 표시.
- 품질 조건: 양쪽에서 동일한 원문 전체를 표시하고, 현행 화면에서 해당 항목을 중복 표시하지 않는다.
- 반복: 독립 렌더링 3회. 고정 CAS/ID/제목/본문과 성공 응답을 사용한다.
- 측정 환경: Vitest + jsdom 컴포넌트 검증. `baseline.tsx`는 위 커밋의 실제 컴포넌트 복사본이며 제품에서 사용하지 않는다.
- 제외 범위: 검색 시작/입력/네트워크/사람의 읽기/검토·승인 시간. 제외한 시간을 절감 성과에 포함하지 않는다.
- 전체 서비스의 클릭 수나 사용자 시간, 현장 대응 효과는 측정하지 않았다.

## 재현 명령

프론트 작업 폴더에서:

```sh
corepack pnpm test src/features/reference/measurement/outcome.test.tsx
node -e 'console.log(require("node:path").join(require("node:os").tmpdir(), "chemicheck119-outcome-measurement/ui-disclosure.json"))'
corepack pnpm check
```

JSON에는 시각, 기준선 커밋, 입력 SHA256, 반복별 추가 조작과 원문 대조 결과가 남는다. 저장된 결과 `measurement/ui-disclosure.json`은 실행 결과 사본이다. test duration은 사용자 작업 시간 또는 성능 지표로 쓰지 않는다.

## 결과와 의미

3회 모두 원문을 펼치는 추가 조작이 1회에서 0회로 바뀌었으며, 양쪽 원문 전체가 일치하고 개선 화면에 항목 1개가 표시됐다. 기존 패널의 접힌 원문을 기본 항목의 즉시 표시로 바꾼 제한된 UI 결과다. 현업 피드백에 대한 설계 변경을 검증했지만, 사용자가 더 빨리 이해했는지는 별도 측정해야 한다.

사용 가능한 표현: “동일 합성 입력을 사용한 3회 화면 검증에서, 조회 후 화재 항목 원문을 펼치는 추가 조작을 1회에서 0회로 줄이고 원문 전체 보존을 확인했다.”

사용 불가능한 표현: 처리량 9배, 성능 800%, 데이터 정확도 100%, 전체 누락률 0%, 소방대원 업무 시간 단축, 상용 운영. 이 변경과 자동 검증은 AI가 수행했다. 사용자가 직접 설계·개발·측정했다고 바꾸지 않는다.

## 실제 사용자 측정 절차 (미실행)

1. 양쪽에 동일한 합성 자료를 제공하는 독립 실습 환경을 준비한다. 실제 승인 자료를 임의 승인하지 않는다. 기존 기준선 조회와 현재 경로가 같은 정보를 제공하는지 먼저 확인한다.
2. 과제: 같은 CAS를 입력하고, 화재 항목의 마지막 제한 문장을 찾아 그대로 말한다. 시작은 검색 입력 시작, 종료는 올바른 마지막 문장 확인이다. 승인 대기/연결 실패는 성공 시간이 아니라 실패로 기록한다.
3. 동일 참여자/장치/입력으로 3쌍을 실행한다. 순서 AB / BA / AB. 키 입력, 클릭, 잘못 찾은 항목과 성공 여부를 기록한다. 작은 표본과 학습 효과를 보고서에 명시한다.
4. `measurement/human-trials.csv`에 관찰값을 넣는다. 실제 참여자 사용 시간과 서버 처리 시간을 섞지 않는다. 승인 시간이 포함되지 않은 조회 실험이므로 갱신 총 업무 시간 단축을 주장하지 않는다.
5. 측정 전에는 시간을 채우지 않는다. 개선이 없거나 내용 찾기가 더 어렵다면 이를 기록하고 정보 구성을 수정한다.

현재 이 사용자 측정은 준비 절차이며 완료 결과가 아니다. 전체 원천 갱신/복구에 대한 개선율도 이번 비교 범위가 아니다.
