# 케미체크119 공모전 통합·시연·발표 런북

이 문서는 추가 모델 개발보다 `FE → BE/BFF → AI` 실제 연결, 재현 가능한 3분 시연, 정확한 10분 발표를 우선하기 위한 단일 체크리스트입니다. 주 시연은 공개 합성 신고를 실제 서버가 처리하는 Contest Live이며, 브라우저 fixture는 인터넷 장애용 백업입니다.

## 1. 통합 기준

```text
FE origin
https://chemicheck119.site

BE/BFF staging
https://chemicheck119-be-staging-w6s6lwanpa-du.a.run.app

AI staging upstream — BE Secret에서만 사용
MODEL_API_BASE_URL=https://chemicheck119-model-api-staging-w6s6lwanpa-du.a.run.app
POST /api/v1/incidents/analyze
X-API-Key: <서버 Secret>
모델 timeout: 15초
FE timeout: 20초
```

- FE는 BFF만 호출합니다. 현재 인증 미사용 staging은 `credentials: omit`, 운영 인증 환경은 HttpOnly session cookie를 위해 `credentials: include`를 사용합니다.
- 모델 API Key는 FE 코드·`VITE_*` 환경변수·브라우저 요청·발표 화면에 넣지 않습니다.
- 업체 이력은 현재 재고가 아니라 ICIS·PRTR 과거 취급 후보입니다.
- 물질명 후보만으로 충돌 규칙을 실행하지 않습니다.
- 사고물질과 시설물질의 CAS 두 개가 모두 현장 확인된 뒤에만 CAMEO 충돌 규칙 결과를 표시합니다.
- 발표 화면에는 `실제 API`와 `공개 합성 신고`가 동시에 보여야 합니다. 전자는 실제 처리 경로, 후자는 입력 데이터의 성격입니다.
- `pnpm dev:demo`의 fixture 화면을 실제 서버 연동 증거로 사용하지 않습니다.

### 신고 입력에 대한 정확한 설명

> 현재 공개 시연은 개인정보가 없는 합성 지령을 사용하지만, 분석은 배포된 FE·BE·AI가 실시간으로 수행합니다. 실제 119 지령 연계는 기관 승인 후 동일한 IncidentEnvelope를 만드는 adapter만 교체하는 단계입니다.

상세 전환 계획은 [신고 입력·시연·실운영 전략](./INCIDENT_INTAKE_STRATEGY.md)을 따릅니다.

## 2. 실제 통합 테스트 3개

### 시나리오 A — 신고문만 입력

행동: 공개 사이트에서 `공개 합성 신고 불러오기`를 누릅니다.

입력:

```text
차아염소산나트륨 저장탱크 누출 의심, 인접 저장고에 염산 표기
```

통과 조건:

- 물질 후보가 표시됩니다.
- `소방안전 빅데이터 기반 후보`와 `현장 확인 필요` 배지가 보입니다.
- 확인 게이트는 `0/2`입니다.
- `conflictReview.executed=false`입니다.
- 위험등급과 대응 RAG는 표시되지 않습니다.

### 시나리오 B — 사고물질 CAS만 확인

행동: 용기 라벨 또는 현장 MSDS 근거를 선택해 사고물질 CAS만 확인합니다.

통과 조건:

- 확인 게이트는 `1/2`입니다.
- 화면은 시설물질 확인을 다음 행동으로 안내합니다.
- 과거 시설 이력은 `ICIS·PRTR 과거 취급 이력`으로 표시되며 현재 재고라고 표현하지 않습니다.
- CAMEO 충돌 규칙은 여전히 실행되지 않습니다.

### 시나리오 C — 두 CAS 모두 확인

행동: 같은 `incidentId`에서 시설물질 CAS도 확인합니다.

통과 조건:

- 확인 게이트는 `2/2`입니다.
- `NOAA CAMEO 충돌 규칙` 배지가 나타납니다.
- 서수 위험등급, 구체적 위험, 대응 근거와 제한사항을 표시합니다.
- 위험등급을 확률이나 안전 판정으로 설명하지 않습니다.
- 최종 판단 주체는 `현장 지휘관`으로 표시됩니다.

### 증적 기록

각 단계에서 다음 값을 함께 보관합니다.

- 실행 시각과 FE origin
- `incidentId`, `requestId`, `analysisId`, `confirmationId`
- HTTP 상태와 총 응답 시간
- 확인 게이트 및 `conflictReview.executed`
- FE 화면 스크린샷
- BE→AI 요청 로그의 상관 ID와 모델 응답 시간

## 3. 3분 시연 대본

### 0:00–0:30 — 신고 접수

“출동 중에는 신고문, 시설 이력, 물질 근거와 충돌 정보를 각각 찾아야 합니다. 케미체크119는 이 과정을 하나의 확인 흐름으로 연결합니다.”

`실제 API`와 `공개 합성 신고` 배지를 먼저 가리킨 뒤 시나리오를 불러와 전송합니다.

“신고문은 개인정보가 없는 합성 시나리오지만, 지금부터의 후보 검색과 근거 생성은 배포된 BE와 AI가 실시간 처리합니다. 실제 119 연계에서는 입력 adapter만 교체합니다.”

### 0:30–1:10 — 후보와 출처

“후보는 소방안전 빅데이터에서 찾고, 시설 정보는 ICIS·PRTR 과거 취급 이력으로 구분합니다. 과거 이력을 현재 재고로 보지 않습니다.”

`AI 확정 아님`, `현장 확인 필요`, 충돌 규칙 `잠김`을 가리킵니다.

### 1:10–1:50 — 첫 번째 CAS 확인

사고물질 CAS를 용기 라벨 또는 현장 MSDS 근거로 확인합니다.

“사고물질만 확인됐으므로 시설물질 확인을 기다립니다. 이 단계에서도 위험등급은 만들지 않습니다.”

### 1:50–2:35 — 두 번째 CAS와 충돌 검토

시설물질 CAS를 확인하고 같은 사고를 재분석합니다.

“두 CAS가 모두 확인된 뒤에만 NOAA CAMEO 결정 규칙을 실행합니다. 화면의 등급은 확률이 아니라 공개 규칙의 서수 결과입니다.”

### 2:35–3:00 — 대응 근거와 책임 경계

KOSHA MSDS 근거, CAMEO 근거, 제한사항과 `최종 판단은 현장 지휘관`을 가리킵니다.

“LLM은 위험을 추측하지 않고 확인된 규칙 결과와 연결된 근거만 요약합니다.”

## 4. 10분 발표 구성

| 구간 | 핵심 메시지 | 시간 |
|---|---|---:|
| 문제 상황 | 출동 중 물질·시설·충돌 정보를 따로 찾아야 합니다. | 1:00 |
| 플랫폼 데이터 활용 | 소방 플랫폼 1,868행을 현장 표현과 CAS 후보 검색에 연결했습니다. | 2:00 |
| 서비스 시연 | 신고 → 후보 → 현장 확인 → 충돌 검토 → 근거 순서입니다. | 3:00 |
| AI 차별성 | Evidence-Gated Agent는 후보만으로 위험을 추측하지 않습니다. | 1:30 |
| 검증·배포 | 외부 보류평가, 자동 테스트, 서울 Cloud Run 배포 결과를 구분해 제시합니다. | 1:30 |
| 기대효과·확장 | 전국 MDT 적용과 대응기록 축적으로 확장합니다. | 1:00 |

## 5. 발표에 사용할 수치

| 항목 | 정확한 표현 |
|---|---:|
| 소방 플랫폼 사고 원천 | 1,868행 |
| 유효 물질명–CAS 표현 | 1,530건 |
| 추가 학습 표현 | 241개 |
| 시간 분할 잠금평가 | 419건 |
| Resolver Top-1 | 32.46% → 67.06% |
| 전국 공식 사고 외부 보류평가 | 442건 |
| 사고유형 Recall | 83.76% |
| 관찰 가능한 물질명 추출 Recall | 81.50% |
| 미확인 후보 충돌 규칙 실행 | 0건 |
| 자동 테스트 | 426개 |
| 배포 | Cloud Run 서울 배포 완료 |

`83.76%`는 전체 AI 정확도가 아니라 전국 공식 사고 외부 보류평가에서 측정한 **사고유형 Recall**입니다.

## 6. 과장 방지 문구

사용하지 않는 표현:

- “AI 정확도가 83.76%입니다.”
- “전국 모든 화학물질을 판정합니다.”
- “업체의 현재 보유물질을 압니다.”
- “전문가 검증이 완료됐습니다.”
- “실제 현장 운영 준비가 끝났습니다.”

권장 표현:

> 다른 기관의 전국 공식 사고 442건으로 파서의 외부 일반화를 감사했으며, 후보만으로 충돌 판정을 실행한 사례는 0건이었습니다.

## 7. 인터넷 장애 대비 녹화

- 브라우저 알림·메신저·개인정보 노출 화면을 닫습니다.
- 발표 해상도와 같은 가로형 태블릿 화면으로 녹화합니다.
- Live 녹화에서는 `실제 API`와 `공개 합성 신고` 배지가 모두 보이는지 확인합니다.
- offline fixture를 사용할 때는 `시연 데이터` 배지가 잘리지 않는지 확인합니다.
- 시나리오 A→B→C를 한 번에 녹화하고 원본 파일을 보존합니다.
- 무음 백업본과 발표 음성 포함본을 각각 준비합니다.
- 발표 노트북 로컬과 USB 또는 별도 저장소에 복제합니다.
- 영상 첫 화면에 `Contest Live`인지 `Offline Demo`인지 명확히 표시합니다.
- 영상 재생 후에도 마지막 결과 화면을 캡처본으로 준비합니다.

## 8. 발표 전 최종 Go/No-Go

- [ ] BE Secret에 모델 URL과 API Key가 설정됐습니다.
- [ ] readiness와 모델 15초 timeout을 확인했습니다.
- [ ] `GET /actuator/info`의 BE commit과 발표 검증 commit을 기록했습니다.
- [ ] 공개 합성 신고로 세 시나리오를 실제 staging에서 실행했습니다.
- [ ] 발표 화면에 `실제 API`와 `공개 합성 신고`가 함께 표시됩니다.
- [ ] 모든 결과 카드에 데이터 출처와 현장 확인 상태가 보입니다.
- [ ] 후보만으로 충돌 규칙이 실행된 요청이 0건입니다.
- [ ] 발표 수치와 Recall 명칭을 교차 검토했습니다.
- [ ] 시연 영상과 결과 캡처를 오프라인에서 재생했습니다.
