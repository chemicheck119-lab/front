# 공개 합성 통합 데모 QA

## 접속

- FE: `https://chemicheck119.site`
- BFF: `https://chemicheck119-be-staging-w6s6lwanpa-du.a.run.app`
- 권장 화면: 가로 1024×768 이상

상단에 `서버 연동`과 `공개 데모 환경`이 보여야 합니다. `오프라인 시연`이 보이면 fixture
환경이므로 Live QA 증적으로 사용하지 않습니다.

## 실제 사용자 단계 QA

1. 좌측 `상황실 연결`을 열고 `지령망 연결`을 누릅니다.
2. `연결 중` 뒤 `새 지령 수신`과 BE 요청 ID가 표시되는지 확인합니다.
3. 지령 내용을 읽고 `지령 확인 및 대응화면에 반영`을 누릅니다.
4. 시설명·주소·신고문과 합성 지도만 반영되고 AI 분석은 아직 없는지 확인합니다.
5. `사고 분석`을 눌러 실제 FE → BE → AI 후보 분석을 실행합니다.
6. 사고물질과 시설물질의 `합성 확인`을 각각 적용해 1/2, 2/2 재분석을 확인합니다.
7. 확인 2/2 이후에만 CAMEO 규칙과 위험 카드가 표시되는지 확인합니다.

지령 수신, 대원 확인, AI 분석은 서로 다른 사용자 행동이어야 합니다. 공개 환경의 두 물질 확인은
실제 현장 확인 폼이 아니라 서버가 고정한 합성 확인임을 화면에서 분명히 표시해야 합니다.

## 자동 통합 QA

1. 초기화 후 `통합 데모 시작`을 누릅니다.
2. 진행표가 `합성 지령 → AI 후보 → 사고물질 → 시설물질 → CAMEO` 순으로 완료되는지 봅니다.
3. 최종 화면에서 `공개 합성 신고`, 필수 CAS `2/2`, 충돌 규칙 `실행됨`, 서수 등급,
   최종 판단 `현장 지휘관`을 확인합니다.
4. 지도에 사고 위치·합성 출동 위치·합성 경로가 함께 보이고 ETA에 `실제 ETA 아님`이 표시되는지 확인합니다.
5. `시연 기록 내보내기` JSON에 `PUBLIC_SYNTHETIC`, `operationalRecord: false`, 분석·확인 ID가 있는지 확인합니다.

추가로 `물질검색`의 `예시 CAS 검색`, `공식 화학자료`, `현재 사고 기록`, 다크 모드,
`사용 종료`를 각각 끝까지 실행합니다. 공개 데모에서는 실제 상황실 전화, 운영 DB 저장,
실제 GPS·도로 길찾기를 사용하지 않습니다.

## 단계별 통과 조건

| 단계 | 서버 동작 | 화면 통과 조건 |
|---|---|---|
| 지령망 연결 | BE SSE `incident.accepted` | 연결 상태와 공개 합성 신고 고지·요청 ID 표시 |
| 대원 확인 | 로컬 대응화면 반영 | 시설·주소·신고문만 입력, AI 분석은 미실행 |
| AI 후보 | FE → BFF → AI | 확인 0/2, 규칙 잠김, 위험 카드 비공개 |
| 사고물질 확인 | 서버 고정 합성 confirmation 후 재분석 | 합성 확인 1/2, 규칙 잠김 |
| 시설물질 확인 | 서버 고정 합성 confirmation 후 재분석 | 합성 확인 2/2 이후에만 CAMEO 규칙 실행 |
| 기록 증적 | 브라우저 JSON 생성 | `operationalRecord: false`, 서버 저장 없음 |

## 실패 시 증적

- 실패한 단계와 화면의 요청 ID
- 브라우저 Network의 요청 URL·HTTP 상태·응답 `error.code`
- 실행 시각(Asia/Seoul)
- 화면 전체 스크린샷

실패를 offline fixture 성공으로 바꾸지 않습니다. `통합 데모 재시도`는 새 SSE incidentId부터 다시
시작합니다.
